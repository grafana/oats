# ADR 0005: Trial Usage Go and Packslip

## Status

Proposed experiment; draft integration, not ready to merge or release.

## Context

OATS has a small CLI and needs a machine-readable CLI description and a
versioned agent skill alongside its binaries. Separately maintained command
metadata would drift from the executable. The existing release pipeline
already publishes archives, checksums, and GitHub build provenance.

## Decision

Define the CLI in a Usage KDL spec and check in Go tables generated by the
pinned Usage CLI. Call the generated `Parse` function for routing and environment
resolution, and use the runtime's help/completion renderers. Convert parsed
strings to application durations/integers without retaining Cobra or pflag.

Keep one run-option declaration under Usage's default `run` command. Optional
config/GCX/LGTM overrides have no spec default, so nonempty supplied values remain
explicit even when they spell the application's usual default. Empty optional
values mean unset, including when they clear an environment override. This
removes the need for general value-source metadata in OATS.

Usage Go is an upstream development preview. Pin generator and runtime to the
same release commit, check reproducibility in CI, and test OATS' documented
contract rather than every incidental Cobra spelling. No KDL parser or Usage
executable is required at runtime.

## Upstream-first merge blockers

- Adopt a matching generator/runtime with
  [Usage #1437](https://github.com/jdx/usage/pull/1437), then remove the temporary
  explicit help-action declaration if the native help behavior is sufficient.
- Submit and adopt the
  [help-topic chain fix](https://github.com/zeitlinger/usage/tree/fix/go-help-topic-chain),
  then replace the local target-to-chain helper with `argv.Walk`. The branch is
  tested and pushed, but GitHub denied upstream PR creation.
- Settle [shared count-env semantics](https://github.com/jdx/usage/discussions/1438).
  OATS temporarily converts only `OATS_VERBOSE`; CLI counts take precedence.
  Also resolve the silent acceptance of attached count values before releasing
  the migration. Do not claim Cobra's `--verbose=3` syntax is supported.
- Regenerate, rerun contract tests, and review the intentional syntax changes
  before moving the OATS PR out of draft. This is not merely waiting for an
  upstream merge.

Packslip publication and the skill do not depend on these parser fixes.

## Release resources

Ship the spec and a consumer-facing `oats` skill inside each release archive.
Publish a signed Packslip manifest after the existing build attestations and
before publishing the draft. Link those attestations rather than replacing or
duplicating them. The skill teaches writing and diagnosing acceptance tests,
not contributing to the OATS repository.

## Consequences

Help and parser-error wording change, and users must regenerate completion
scripts. Native Usage grammar replaces Cobra-specific boolean/count spellings;
see [the CLI reference](../cli.md) for the intentional differences. Runtime-
dependent defaults remain in Go. A small count-env conversion and help-topic
lookup are explicitly temporary, not foundations for a second parser.

Packslip 1.2 defaults Linux artifacts to `gnu`. It cannot omit only libc through
its generator, so musl consumers must still download the libc-independent Linux
archives directly. Do not claim all-platform portability to bypass that limit.

Revisit this experiment if upstream parser compatibility or release metadata
limitations impose substantial maintenance. The KDL and skill remain useful
release resources even if the parser or manifest tooling is replaced.
